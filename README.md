# AI 데이터센터 열섬 — 재현 가능한 검증

> **묻는 것**: AI 데이터센터(AIDC)가 들어설 산업단지·폐공장 부지는 이미 주변보다 뜨거운가. 그 열이 더해지면 누가 얼마나 더 아픈가.
>
> **정책 고리**: AIDC 특별법은 기존 산단 입지 시 환경영향평가를 생략할 수 있게 한다. 그리고 평가 항목에 **「열섬」이라는 이름의 항목은 없다** — 다만 「기상」 항목이 온도 변화 예측을 요구하는데, 그 의무가 *"댐 건설·대규모 지형 변화"*와 *"도심지역 도시개발사업"*이라는 **예시로 좁혀져** 데이터센터를 비껴간다. 지형을 바꾸지 않고 열만 내는 시설이 두 예시 사이로 빠진다.

작성 2026-07-28 · **공개 저장소** · 원 작업 저장소에서 공개 가능한 부분만 떼어냈다.

---

## 1. 결론부터

| | |
|---|---|
| **부지는 이미 뜨겁다** | 위성 90여 장면으로 11개 부지 측정. 주변 10~20km 대비 **+5.5 ~ +17.3℃**(지표온도). 기준을 주거지 화소로 좁혀도 **+1.4 ~ +10.5℃** |
| **열은 거리에 따라 식는다** | 케임브리지 논문이 보고한 3점에 세 형태를 적합 → **지수형만 통과**(반감기 4.2km) |
| **기온으로 옮기면 훨씬 작다** | 지표→기온 환산계수 β = **0.258**(우리 관측소 회귀). 0.5km **+0.49℃** … 7.25km **+0.16℃** |
| **그래서 추가 환자는 크지 않다** | 인천 폐공장 시나리오 **약 13건/년**(10km 누적 236만 명 기준) |
| **작다는 것이 곧 안전은 아니다** | 열은 사라지지 않는다. 기온이 덜 오르면 그만큼 **물이 가져갔다는 뜻**이다 |

**노출 인구는 확정값이다** — 인천 10km 안 **236만 명**(고령 41만). 집계구 실측이라 가정이 없다.

## 2. 구조

```
├── 요약_결과노트북_2026-07-28.ipynb        ★ 여기부터 — 결과만 선형으로
├── 산업전력_검증노트북_2026-07-18.ipynb     본 분석 169셀 (사고 과정 그대로)

├── data/                                  자료 49개 · 267MB
│   ├── DERIVED_*.csv (23)                 집계본 — 시군구·부지 단위
│   └── OPEN_*.xlsx/csv (26)               공공 원자료 (한전·기상청·산단공·통계청)
├── docs/                                  논증 · 팩트시트 · 재현성 점검 · 에너지바우처
├── figures/거리감쇠곡선.html                 브라우저로 바로 열림
```

**자료는 `data/` 한 폴더에 있다.** 노트북 첫 셀이 알아서 그 폴더로 이동하므로, 저장소 루트에서 열어도 그대로 돌아간다.

- **`요약_결과노트북`** — `data/DERIVED_*.csv` 만으로 전 셀이 돈다. 몇 초면 끝난다.
- **`산업전력_검증노트북`** — 공공 원자료가 `data/`에 있어 대부분 돈다. 다만 **온열질환 원자료가 필요한 셀은 못 돈다**(아래 §4).
- **`Landsat_LST_파이프라인`** — 위성영상 36GB가 따로 필요하다. `_원자료_목록.md` 참조.

## 4. 없는 것 — 그리고 왜

**① 질병관리청 NEDIS 온열질환 원자료**

정보공개청구로 받은 자료인데 **환자 1명당 1행**(15,000행)이고 `발생일자·발생시간·성별·나이·발생시군구·진료결과`를 포함한다. 이름이 없어도 작은 지자체에서는 **재식별 위험이 실재**한다. 공개 저장소에 올리지 않는다.

→ 대신 이 자료로 만든 **집계본**을 넣었다(`DERIVED_0725_시군구_발생장소_여름집계.csv` 등). 시군구·일자 단위라 개인이 식별되지 않는다.

**② 원본 위성영상** (36GB) — 용량. USGS에서 누구나 같은 장면을 받을 수 있다.

**③ 100MB 초과 파생물** — `DERIVED_0725_기준도넛_피복마스크`. 노트북에서 재생성된다.

> 공개 전 파일 **내용**을 정밀 검사했다 — 주민번호·전화·이메일·키 패턴, 그리고 개인 단위 열(성별·나이·발생시간·보고번호…) 조합. **FAIL 0건.**

## 5. 이 노트북을 읽는 법 — 우리가 틀린 자리도 남겨두었다

이 저장소의 특징은 **정답만 담지 않았다는 것**이다. 본 검증 노트북 셀 1의 변경 이력에 **자기수정 11건**이 근거와 함께 적혀 있다. 예를 들어:

- "3km까지 기온 +2℃" 평평 가정을 **폐기**했다 → 추가온열 추정이 6~7배 내려갔다
- "광양 3km에 73명이 산다"는 대표좌표가 **바다에 찍혀** 생긴 값이었다 → 실형상으로 재니 72,511명
- 케임브리지(위성·링평균)와 Sailor(차량·풍하최대)를 하나의 기하로 **화해시키려다 실패**했다 → 미해결로 남겼다

그 과정에서 세운 규칙 넷:

> **1.** "A라서 B"라고 쓰기 전에 B를 잰 줄이 있는지 확인한다
> **2.** 통제변수는 그 **반사실 값을 정할 수 있을 때만** 넣는다. AIC·R²는 인과 설계의 근거가 아니다
> **3.** 문헌 계수는 **우리 자료에 대입해 보고 나서** 논증에 얹는다
> **4.** **모수를 풀어서 맞춘 값은 증거가 아니다.** 실패할 수 없는 계산은 아무것도 확인해주지 않는다

## 6. 아직 못 한 것 (반박 환영)

| | |
|---|---|
| **β의 정체** | 우리 β=0.258은 *서로 다른 장소*를 비교해 얻었다. "한 곳에 열을 부으면 얼마나 오르나"와 다르다. **한국에서 가동 중인 데이터센터 주변을 차량으로 실측**하면 이 구멍이 직접 메워진다 |
| **β 상한 0.459** | σ_e를 *풀어서* 얻은 값이라 민감도가 극단이다(±0.25℃ → β 2배). **"상한 후보"로만** 쓰고 단독 인용하지 않는다 |
| **플룸(바람 방향)** | 우리 ΔT는 **등방**(사방 균일)이다. 열이 바람 쪽으로 몰리면 dose가 볼록해 추가 환자가 **오히려 늘어난다**. 모형이 들어오면 꽂을 자리(`register_plume`·`dT_field`·`excess_plume`)를 만들어 두었다 |
| **포항·여수 경계** | 산단 실형상 자료가 없어 대표좌표 폴백을 썼다. 그 값은 **하한**이다 |
| **물** | 열의 대부분이 물로 나간다는 것까지는 계산했지만, 실제 취수원·방류 계획은 모른다 |
