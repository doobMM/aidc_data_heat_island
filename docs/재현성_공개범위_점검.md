# 재현성 점검 — `OPEN_`·`DERIVED_`만 공개해도 어디까지 재현되나

> 📅 **갱신 이력(최신순)**
> - **2026-07-25**: 최초 작성. 질문 — "FOIA로 시작하는 파일을 올리지 않고 OPEN·DERIVED CSV만 push해도 재현성이 확보되나?"
>
> 대상 노트북: `산업전력_검증노트북_2026-07-18.ipynb` (139셀 기준)
> 방법: 노트북 전 코드셀에서 파일 참조를 추출해 절(§)별로 매핑 후, 각 절이 어떤 입력에 의존하는지 확인.

## 결론 먼저

**아니요 — 절반만 재현됩니다.** 정확히는 이렇습니다.

| | 재현 여부 | 이유 |
|---|---|---|
| **§2·§3·§5** 전력 추이·폐산단 스캔 | ✅ 완전 | `DERIVED_0718_시군구_계약종별_다년전력.csv`만 있으면 됨 |
| **§4·§8·§12-c** | ✅ 완전 | 패널 CSV + 산단공 OPEN 엑셀 |
| **§6** 발생장소 판별 | ❌ 불가 | NEDIS **원자료의 `발생장소` 열**을 직접 읽음. 집계 CSV엔 없음 |
| **§9-①·c·d·e** dose-response 회귀 | ❌ 불가 | NEDIS **일자별** 건수 필요. 패널 CSV는 **연도 단위**라 일별 Poisson을 못 돌림 |
| **§10~§13·§18-b2** 추가온열 추정 | ⚠️ 부분 | 인구·버퍼는 되지만 **`BETA_SITE`(§9-e 산출)가 없으면 `f_site()`가 못 돈다** |
| **§11** 연령가중 | ❌ 불가 | 65+ 상대위험 `RR`을 NEDIS 원자료 나이 열에서 직접 계산 |
| **§14·§15·§17** 위성·환산·녹지 | ⚠️ 부분 | 원본 Landsat(36GB)은 못 올리지만, **중간 산출 CSV가 있어 하류 분석은 재현됨** |

즉 **"전력·면적·인구·위성 계열은 되고, 온열질환(NEDIS)이 들어가는 계열은 막힙니다."** NEDIS가 결과변수라 사실상 논증의 절반입니다.

## 1. 막히는 지점 3개와 해소 방법

FOIA 원본을 올리지 않고도 뚫으려면 **집계 산출물 3개를 새로 export**하면 됩니다. 개인 단위 정보가 아니라 이미 집계·추정된 값이므로 공개해도 프라이버시 문제가 없고, 오히려 원자료를 안 올리는 게 안전합니다.

| # | 막히는 것 | 필요한 신규 export | 담기는 내용 |
|---|---|---|---|
| 1 | §9-e `BETA_SITE` → §10~§18 전부 | `DERIVED_0725_부지별_dose배수.csv` | 시군구 key · 채택 배수 m_s · 채택 근거(시군구/시도) · n · 최근접 관측소 거리 |
| 2 | §11 연령가중 `RR`·`E_ELD`·`E_YNG` | `DERIVED_0725_연령가중_계수.csv` | NAT65 · RR · E_ELD · E_YNG (전국 1행) |
| 3 | §6 발생장소 상관 | `DERIVED_0725_시군구_발생장소_여름집계.csv` | 시군구 × 발생장소(집·길가·실외작업장…) 여름 건수 |

3번은 시군구×장소 집계라 셀 크기가 작을 수 있으니, **5건 미만 셀은 마스킹**하는 게 안전합니다(재식별 방지).

> ⚠ 위 3개는 아직 **만들지 않았습니다.** 만들려면 노트북에 export 셀을 추가하고 한 번 돌려야 합니다.

## 2. 그래도 남는 제약 — 일별 자료

§9-①(전국 기온→온열 곡선)과 §9-c/d(지역별 Poisson)는 **일자별** 온열 건수를 씁니다. 이걸 공개하려면 시도(또는 시군구)×일자 건수를 내보내야 하는데, 시군구×일자는 대부분 0~2건이라 재식별 위험이 있습니다.

**권고**: 시도×일자까지만 공개(`DERIVED_..._시도일자_온열.csv`). 그러면 §9-c(시도 FE)는 재현되고, §9-d(시군구 FE)는 "원자료 필요" 상태로 남습니다. §9-e는 시도 폴백 규칙으로 부분 재현됩니다.

## 4. 파일 크기 주의

GitHub는 100MB 초과 파일을 거부하고 50MB 초과는 경고합니다. 현재 `DERIVED_`는 전부 통과하지만 두 개가 큽니다:

- `DERIVED_0723_링화소_NDVI_LST표본.csv` — **29.8MB**
- `DERIVED_0724_피복별_LST표본.csv` — **15.5MB**

둘 다 화소 표본이라 **행 수를 줄이면(예: 30만 → 10만) 결론이 바뀌지 않습니다**(§17-b 기울기는 이미 305만 화소 기반이고 표본은 확인용). 필요하면 축소본을 올리고 전체는 메일로 공유하는 방식이 낫습니다.

## 5. 권고 — 3단계

1. **지금 바로 올릴 수 있는 것**: `OPEN_*` 전부 + `DERIVED_*` 전부 + **ILIS shapefile 2종(11.5MB)**
   → §2·§3·§4·§5·§7·§8·§12-c 완전 재현, §14·§15·§17 하류 재현
2. **export 3개 추가 후**: §10~§13·§18 추가온열 추정이 재현됨 (위 표의 1·2번)
3. **시도×일자 온열 공개 시**: §9-c·§9-e 부분 재현 → 사실상 전 파이프라인

**§6(발생장소)만 원자료급 정보가 필요**한데, 이건 "산업↔온열은 작업장 노동이지 열섬이 아니다"라는 **우리 논증의 자기 규율 근거**라서 검증 가능하게 만드는 게 중요합니다. 3번 export(5건 미만 마스킹)로 해결하는 걸 권합니다.
